🎯 What is it?

CI/CD & Parallel Execution

Think of a checkout line at a grocery store: one cashier (sequential) vs four lanes (workers) vs four stores in the city (sharding). Playwright scales the same way — workers parallelize on one machine; shards split across multiple CI runners.

GitHub Actions runs your suite on every push and PR — with artifacts, traces, and merged reports when tests fail.

💻 Code Example

GitHub Actions Setup

# .github/workflows/playwright.yml
name: Playwright Tests
on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    timeout-minutes: 30
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci
      - run: npx playwright install --with-deps chromium
      - run: npx playwright test
      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: playwright-report
          path: playwright-report/
      - uses: actions/upload-artifact@v4
        if: failure()
        with:
          name: test-results
          path: test-results/

⚙️ How It Works

Parallel Workers

Each worker is a separate process with its own browser. Tests are distributed automatically; results merge into one report.

export default defineConfig({
  workers: process.env.CI ? 1 : undefined,  // 1 per shard in CI
  // workers: 4,
  // workers: '50%',
  fullyParallel: true,
});

// Parallel by default within describe
test('add item', async ({ page }) => { /* worker A */ });
test('remove item', async ({ page }) => { /* worker B */ });

// Serial when tests share state
test.describe.configure({ mode: 'serial' });
test.describe('Checkout Flow', () => {
  test('fill shipping', async ({ page }) => { /* same worker */ });
  test('confirm order', async ({ page }) => { /* same worker */ });
});
🔄 Real-Life Example

Test Sharding

Four CI machines each run 25% of the suite — like four assembly lines building one car together.

strategy:
  fail-fast: false
  matrix:
    shardIndex: [1, 2, 3, 4]
    shardTotal: [4]

- run: npx playwright test --shard=${{ matrix.shardIndex }}/${{ matrix.shardTotal }}

# Blob reporter per shard, then merge:
reporter: process.env.CI ? [['blob'], ['github']] : [['html'], ['list']]

# merge-reports job
- run: npx playwright merge-reports --reporter html ./all-blob-reports
💻 Code Example

E-Commerce Production Config

const isCI = !!process.env.CI;

export default defineConfig({
  fullyParallel: true,
  workers: isCI ? 1 : undefined,
  forbidOnly: isCI,
  retries: isCI ? 2 : 0,
  timeout: 60000,

  reporter: isCI
    ? [['blob'], ['github'], ['json', { outputFile: 'test-results.json' }]]
    : [['html'], ['list']],

  use: {
    baseURL: process.env.BASE_URL || 'https://staging.shop.example.com',
    trace: 'on-first-retry',
    screenshot: 'only-on-failure',
    video: 'on-first-retry',
  },

  projects: [
    { name: 'setup', testMatch: /.*\.setup\.ts/ },
    {
      name: 'chromium',
      use: { ...devices['Desktop Chrome'], storageState: 'playwright/.auth/user.json' },
      dependencies: ['setup'],
    },
    {
      name: 'firefox',
      use: { ...devices['Desktop Firefox'], storageState: 'playwright/.auth/user.json' },
      dependencies: ['setup'],
      grep: /@smoke/,
    },
    {
      name: 'mobile-chrome',
      use: { ...devices['Pixel 5'], storageState: 'playwright/.auth/user.json' },
      dependencies: ['setup'],
      grep: /@mobile/,
    },
  ],
});

✅ Best Practices

CI Best Practices

  • Cache browsers — ~/.cache/ms-playwright keyed on lockfile
  • Secrets for staging — BASE_URL, test user credentials
  • Smoke then full — fast @smoke gate before 4-shard full suite
  • Nightly cron — all browsers at 2 AM UTC
  • PR annotations — --reporter=github inline on diffs

⚠️ Watch Out!

Common Mistakes

  • ❌ Parallel tests sharing cart/session state: Worker A clears cart Worker B needs.
    ✅ Isolated test data per test or mode: 'serial' for dependent flows.
  • ❌ Many workers + many shards without tuning: Overwhelming staging server.
    ✅ workers: 1 per shard in CI — scale machines, not processes per machine.
  • ❌ Forgetting blob reporter when sharding: Can't merge HTML reports.
    ✅ ['blob'] reporter + merge-reports job.
  • ❌ Leaving test.only in code: CI runs one test, green build lies.
    ✅ forbidOnly: isCI fails the build.
📝 Summary

Key Takeaways

  • GitHub Actions integrates seamlessly with Playwright
  • Workers parallelize within a machine
  • Sharding distributes across machines — unlimited scale
  • Blob reporter enables merging sharded reports
  • Tags — @smoke, @mobile for selective runs
  • Cache browsers — faster CI installs
  • API setup — eliminate slow UI login per test
  • Monitor flakiness — JSON results + retries analysis
