🎯 What is it?

Setup & First Test

This lesson is your day-one hands-on start. By the end, you'll have Playwright installed, a real checkout test running against a public demo store, and a config file tuned for e-commerce.

Think of it like setting up a new kitchen before cooking — install the appliances (browsers), lay out your workspace (project folders), then cook your first meal (run a test).

i

We use Sauce Demo (saucedemo.com) — a free public e-commerce practice site. No signup needed.

📋 Before You Start

Prerequisites

You need Node.js 18 or higher — that's the engine that runs Playwright on your machine, like electricity for your kitchen appliances.

node --version
# Should show v18.x.x or higher
🏪 Real-Life Example

Installation

Installing Playwright is like buying a starter kit — one command gives you the test runner, example files, config, and browser downloads.

1
Option 1: New Project (Recommended)
Learning 
mkdir ecommerce-tests
cd ecommerce-tests
npm init -y
npm init playwright@latest

The wizard asks a few questions — pick TypeScript, put tests in tests/, and say yes to installing browsers:

✔ Do you want to use TypeScript or JavaScript? › TypeScript
✔ Where to put your end-to-end tests? › tests
✔ Add a GitHub Actions workflow? › true
✔ Install Playwright browsers? › true
2
Option 2: Existing Project
Add-on 
npm install -D @playwright/test
npx playwright install
📊 What You Get

What Gets Installed?

When you run npx playwright install, Playwright downloads its own browser copies — like a film studio keeping exact camera models on set, not whatever happens to be in your pocket.

These are not your everyday Chrome or Safari. Playwright installs specific versions it has tested against.

Browser Engine Size
ChromiumChrome / Edge~280 MB
FirefoxMozilla~250 MB
WebKitSafari~180 MB

⚙️ Setup

The Config File

playwright.config.ts is the control panel for your whole test suite — which browsers, how long to wait, what to capture on failure. Set it once, every test inherits the rules.

3
Default Config
import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  testDir: './tests',
  fullyParallel: true,
  forbidOnly: !!process.env.CI,
  retries: process.env.CI ? 2 : 0,
  workers: process.env.CI ? 1 : undefined,
  reporter: 'html',
  use: {
    baseURL: 'https://shop.example.com',
    trace: 'on-first-retry',
    screenshot: 'only-on-failure',
  },
  projects: [
    { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
    { name: 'firefox', use: { ...devices['Desktop Firefox'] } },
    { name: 'webkit', use: { ...devices['Desktop Safari'] } },
  ],
});

import { test, expect } from '@playwright/test';

test.describe('Product Page', () => {
  test('displays product details correctly', async ({ page }) => {
    await page.goto('https://demo.playwright.dev/svgomg');
  // Replace with your actual e-commerce URL when ready

    await expect(page).toHaveTitle(/SVGOMG/);
  });
});
🛒 Real-Life Example

Full E-Commerce Flow

Now the real thing — login, browse, add to cart, and checkout on Sauce Demo. It's like being a mystery shopper: follow the customer journey and verify every step worked.

Create tests/ecommerce.spec.ts:

5
E-Commerce Test Suite
Sauce Demo 
import { test, expect } from '@playwright/test';

const BASE_URL = 'https://www.saucedemo.com';

test.describe('E-Commerce Product Flow', () => {
  test.beforeEach(async ({ page }) => {
    await page.goto(BASE_URL);
    await page.getByPlaceholder('Username').fill('standard_user');
    await page.getByPlaceholder('Password').fill('secret_sauce');
    await page.getByRole('button', { name: 'Login' }).click();
    await expect(page.getByText('Products')).toBeVisible();
  });

  test('can view product details', async ({ page }) => {
    await page.getByText('Sauce Labs Backpack').click();
    await expect(page.getByText('Sauce Labs Backpack')).toBeVisible();
    await expect(page.getByText('$29.99')).toBeVisible();
    await expect(page.getByRole('button', { name: 'Add to cart' })).toBeVisible();
  });

  test('can add product to cart', async ({ page }) => {
    await page.getByRole('button', { name: 'Add to cart' }).first().click();
    await expect(page.locator('.shopping_cart_badge')).toHaveText('1');
  });

  test('can complete checkout flow', async ({ page }) => {
    await page.getByRole('button', { name: 'Add to cart' }).first().click();
    await page.locator('.shopping_cart_link').click();
    await expect(page.getByText('Your Cart')).toBeVisible();

    await page.getByRole('button', { name: 'Checkout' }).click();
    await page.getByPlaceholder('First Name').fill('John');
    await page.getByPlaceholder('Last Name').fill('Doe');
    await page.getByPlaceholder('Zip/Postal Code').fill('12345');
    await page.getByRole('button', { name: 'Continue' }).click();

    await expect(page.getByText('Checkout: Overview')).toBeVisible();
    await page.getByRole('button', { name: 'Finish' }).click();
    await expect(page.getByText('Thank you for your order!')).toBeVisible();
  });
});
✓

Quick tip: beforeEach logs in before every test — like unlocking the store door once before each mystery-shopping round, not re-locking between aisles.

▶️ Action

Running Tests

Running tests is like choosing how to watch a sports game — highlights only (headless), live in the stadium (headed), or replay with commentary (UI mode).

Command What it does
npx playwright testRun all tests (headless)
npx playwright test tests/ecommerce.spec.tsRun one file
npx playwright test --headedWatch the browser
npx playwright test --uiInteractive UI mode
npx playwright test -g "can add product to cart"Run one test by name
npx playwright test --project=firefoxRun in Firefox only

Example output:

  ✓ [chromium] tests/ecommerce.spec.ts:15:7 › can view product details (2.3s)
  ✓ [chromium] tests/ecommerce.spec.ts:24:7 › can add product to cart (1.8s)
  ✓ [chromium] tests/ecommerce.spec.ts:31:7 › can complete checkout flow (3.1s)

📊 Reading Results

Understanding Test Output

Open the HTML report after a run — it's like a scorecard with instant replay:

npx playwright show-report

The report shows pass/fail status, duration, screenshots on failure, and traces (if enabled).

Reading the console line by line:

Running 3 tests using 3 workers
              ↑              ↑
         Total tests    Parallel processes

  ✓ [chromium] tests/ecommerce.spec.ts:15:7 › can view product details
    ↑           ↑                      ↑
  Browser    File path            Line number

UI mode (--ui) lets you watch tests live, see DOM snapshots at each step, filter tests, and time-travel through execution — great for learning.

🛒 E-Commerce

Project Configuration for E-Commerce

Checkout flows are slow — payment pages, shipping forms, inventory checks. Your config needs longer patience, like giving a busy restaurant more time before you assume the order failed.

6
E-Commerce Tuned Config
import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  testDir: './tests',
  fullyParallel: true,
  forbidOnly: !!process.env.CI,
  retries: process.env.CI ? 2 : 0,
  workers: process.env.CI ? 1 : undefined,
  reporter: [['html'], ['list']],
  timeout: 60000,

  use: {
    baseURL: process.env.BASE_URL || 'https://www.saucedemo.com',
    screenshot: 'only-on-failure',
    video: 'on-first-retry',
    trace: 'on-first-retry',
    actionTimeout: 15000,
    navigationTimeout: 30000,
  },

  projects: [
    { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
    { name: 'firefox', use: { ...devices['Desktop Firefox'] } },
    { name: 'webkit', use: { ...devices['Desktop Safari'] } },
    { name: 'mobile-chrome', use: { ...devices['Pixel 5'] } },
    { name: 'mobile-safari', use: { ...devices['iPhone 13'] } },
  ],
});
💻 Code Example

Useful Scripts in package.json

Shortcuts in package.json are like speed-dial buttons — one tap instead of typing the full command every time.

{
  "scripts": {
    "test": "playwright test",
    "test:headed": "playwright test --headed",
    "test:ui": "playwright test --ui",
    "test:debug": "playwright test --debug",
    "test:chrome": "playwright test --project=chromium",
    "test:mobile": "playwright test --project=mobile-chrome --project=mobile-safari",
    "report": "playwright show-report"
  }
}
npm test              # Run all tests
npm run test:headed   # Watch tests run
npm run test:ui       # Interactive UI mode
npm run test:mobile   # Mobile browser tests only
⚠️ Watch Out!

Common Mistakes

  • ❌ "Browser not found" error: You skipped browser install or deleted the cache.
    ✅ Run npx playwright install to download browsers again.
  • ❌ Timeout errors on checkout: Default 30s isn't enough for slow payment pages.
    ✅ Raise actionTimeout and navigationTimeout in config for e-commerce flows.
  • ❌ Tests pass locally, fail in CI: Your laptop is fast; CI runners are slower.
    ✅ Enable trace: 'on' in CI and download artifacts to debug with Trace Viewer.
  • ❌ Using brittle CSS classes like .shopping_cart_badge: Works today, breaks when devs refactor.
    ✅ We'll fix this in the next lesson with resilient locator strategies — for now, notice the problem.
📝 Summary

Key Takeaways

  • Installation is simple: npm init playwright@latest handles everything
  • Browsers are managed: Playwright installs and updates its own copies
  • Config is powerful: Control timeouts, browsers, reporters, and failure capture
  • Multiple run modes: Headless, headed, UI mode, debug mode
  • E-commerce ready: Longer timeouts and mobile projects matter for shop sites
  • HTML reporter: Built-in beautiful test reports with show-report
