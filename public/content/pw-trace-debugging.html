Debugging with Traces

CI says "Element not found." You have no idea what the page looked like. Playwright's debugging tools are like a black box flight recorder for every test run.

🎯 What is it?

Debugging with Trace Viewer

When a test fails remotely, you're debugging blind — like diagnosing a car problem from a text message. Traces record screenshots, DOM, network, and console at every step so you can rewind and see exactly what happened.

Locally, Inspector and UI Mode let you step through tests like a debugger in your IDE.

💻 Code Example

Playwright Inspector

# Debug a specific test
npx playwright test cart.spec.ts --debug

# Debug from line 25
npx playwright test cart.spec.ts:25 --debug

Inspector opens with:

  • Browser window — your app live
  • Step panel — execute one line at a time
  • Pick Locator — click elements, get suggested locators
// Try locators live in Inspector console
page.getByRole('button', { name: 'Add to Cart' })
page.locator('.cart-count').count()
💻 Code Example

Breakpoints & PWDEBUG

test('checkout flow', async ({ page }) => {
  await page.goto('/products/laptop');
  await page.getByRole('button', { name: 'Add to Cart' }).click();

  await page.pause();  // Pauses when run with --debug

  await page.goto('/checkout');
});

# Enable Inspector for all tests
PWDEBUG=1 npx playwright test

# Console mode (no GUI)
PWDEBUG=console npx playwright test
⚙️ Configuration

Enabling Traces

Traces are recordings of everything during a test — essential for CI post-mortems.

// playwright.config.ts
export default defineConfig({
  use: {
    trace: 'on-first-retry',    // Record on retry (saves CI time)
    // trace: 'on',             // Always record
    // trace: 'retain-on-failure', // Keep only failed test traces
  },
});

🔍 Real-Life Example

Debugging "Element not visible"

  1. Open trace in Trace Viewer
  2. Find the failing action on the timeline
  3. Click — see screenshot at that moment
  4. Check DOM snapshot — is the element there?
  5. Check Network — did the API finish?
  6. Look at the action before — unexpected overlay?
💻 Code Example

UI Mode

Interactive test development — like a video editor for your test run. Save a file and tests re-run automatically.

npx playwright test --ui
  • Watch mode — re-run on save
  • Time-travel — scrub timeline, see page at any action
  • Filtering — run one file or failed tests only
  • Live locators — hover actions to see targeted elements
⚠️ Real-Life Example

Debugging Flaky Tests

Flaky tests pass sometimes, fail sometimes — compare passing vs failing traces side by side.

// Gather data
use: { trace: 'on' },
retries: 3,
1
Element not stable
// FLAKY
await page.locator('.notification').click();

// FIXED — wait for visible/stable
await expect(page.locator('.notification')).toBeVisible();
await page.locator('.notification').click();
2
Stale cart count
// FLAKY
const count = await page.locator('.cart-count').textContent();

// FIXED
await expect(page.locator('.cart-count')).toHaveText('1');
3
Navigation race
await page.getByRole('link', { name: 'Checkout' }).click();
await page.waitForURL('**/checkout');
await expect(page.getByText('Checkout')).toBeVisible();
4
Cookie banner blocking
const cookieBanner = page.getByRole('button', { name: 'Accept Cookies' });
if (await cookieBanner.isVisible({ timeout: 1000 }).catch(() => false)) {
  await cookieBanner.click();
}

E-Commerce Debugging

// Payment — log requests in trace console
page.on('request', req => {
  if (req.url().includes('/api/payment')) console.log('Payment:', req.postData());
});
page.on('response', res => {
  if (res.url().includes('/api/payment')) console.log('Status:', res.status());
});

// Cart persistence — log storage after each test
test.afterEach(async ({ context }) => {
  const storage = await context.storageState();
  console.log('Cookies:', storage.cookies);
});
🔄 CI

CI Debugging Workflow

# GitHub Actions — upload on failure
- name: Upload traces on failure
  if: failure()
  uses: actions/upload-artifact@v4
  with:
    name: playwright-traces
    path: test-results/

# Locally after download
npx playwright show-trace test-results/*/trace.zip
npx playwright show-report playwright-report
⚠️ Watch Out!

Common Mistakes

  • ❌ No traces in CI: "Element not found" with zero context.
    ✅ trace: 'on-first-retry' or retain-on-failure + upload artifacts.
  • ❌ Only reading the error message: Skipping Trace Viewer.
    ✅ Always open the trace — screenshot at failure often explains everything.
  • ❌ Adding waitForTimeout to fix flakes: Masks timing without fixing root cause.
    ✅ Web-first assertions, waitForURL, dismiss overlays — use trace to see the race.
  • ❌ trace: 'on' for every test in CI always: Huge artifacts, slow runs.
    ✅ on-first-retry balances storage vs debuggability.
📝 Summary

Key Takeaways

  • Inspector (--debug) — step-through, pick locators
  • page.pause() — breakpoints in test code
  • Trace Viewer — screenshots, DOM, network at every step
  • UI Mode (--ui) — watch mode + time-travel
  • Flaky tests — compare pass vs fail traces
  • CI — enable traces, upload artifacts on failure
