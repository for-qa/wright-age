Locator Strategies

The #1 reason tests break after deployments? Brittle locators. A developer changes a CSS class, and suddenly 50 tests fail. Let's fix that.

Golden Rule
🎯 What is it?

Locator Strategies

A locator is how your test finds an element on the page — like giving directions to a friend. "The red house on Oak Street" breaks when they repaint it. "The house with the mailbox that says Smith" survives a new paint job.

Playwright locators should match how users see the page (buttons, labels, headings) — not how developers styled it yesterday (CSS class names).

i

In Topic 2 we used .shopping_cart_badge — that was intentional. This lesson shows you the resilient replacements.

📊 Comparison

The Locator Hierarchy

Playwright recommends locators in this priority order — top = most stable, bottom = last resort:

1. getByRole()     → Best: matches how users see the page
2. getByText()     → Good: visible text content
3. getByLabel()    → Good: form accessibility
4. getByTestId()   → Good: explicit test contracts
5. CSS selectors   → Okay: when nothing else works
6. XPath           → Last resort: complex DOM traversal

Why this order? If your "Add to Cart" button changes from class="btn-primary" to class="ProductCard__button", a CSS selector breaks. But getByRole('button', { name: 'Add to Cart' }) keeps working — users still see a button with that label.

💻 Code Example

Role-Based Locators (Best Practice)

getByRole() is like asking a screen reader what’s on the page — it finds elements by their ARIA role and accessible name.

1
Common E-Commerce Roles
// Buttons
await page.getByRole('button', { name: 'Add to Cart' }).click();
await page.getByRole('button', { name: 'Proceed to Checkout' }).click();

// Links
await page.getByRole('link', { name: 'View Details' }).click();

// Headings
await expect(page.getByRole('heading', { name: 'Shopping Cart' })).toBeVisible();

// Navigation
await page.getByRole('navigation').getByRole('link', { name: 'Products' }).click();

// Form elements
await page.getByRole('textbox', { name: 'Email' }).fill('john@example.com');
await page.getByRole('spinbutton', { name: 'Quantity' }).fill('3');
await page.getByRole('checkbox', { name: 'Subscribe to newsletter' }).check();
await page.getByRole('combobox', { name: 'Country' }).selectOption('United States');

🔤 Matching

Name Matching Options

Names are like calling someone by nickname vs full name — Playwright lets you be exact or flexible:

// Exact match (default)
page.getByRole('button', { name: 'Add to Cart' });

// Case-insensitive
page.getByRole('button', { name: 'add to cart', exact: false });

// Regex pattern
page.getByRole('button', { name: /add to cart/i });

// Partial heading match
page.getByRole('heading', { name: /checkout/i });
💻 Code Example

Text-Based Locators — getByText()

getByText() finds what the shopper actually reads on screen — product names, prices, success messages.

await page.getByText('Wireless Bluetooth Headphones').click();
await expect(page.getByText('$129.99')).toBeVisible();
await expect(page.getByText('Item added to cart')).toBeVisible();
await expect(page.getByText('Order confirmed')).toBeVisible();

// Partial match
await page.getByText('Free shipping', { exact: false }).click();
🏪 Real-Life Example

getByLabel() — Forms & Checkout

Checkout forms are like filling out a paper form — each field has a printed label. getByLabel() targets that label, which is how assistive tech finds fields too.

await page.getByLabel('First Name').fill('John');
await page.getByLabel('Last Name').fill('Doe');
await page.getByLabel('Email Address').fill('john@example.com');
await page.getByLabel('Credit Card Number').fill('4111111111111111');

await page.getByLabel('Standard Shipping ($5.99)').check();
await page.getByLabel('Express Shipping ($15.99)').check();
💻 Code Example

getByPlaceholder()

When labels are missing (common on older sites), the placeholder hint inside the box is your fallback — like the faint "Search..." ghost text.

await page.getByPlaceholder('Search products...').fill('laptop');
await page.getByPlaceholder('Enter promo code').fill('SAVE20');
⚠

Prefer getByLabel() when labels exist — placeholders disappear once you type.

🏷️ Test Contracts

Test ID Locators — getByTestId()

When you control the app, data-testid is a handshake between dev and QA — "this attribute is for tests only; don't remove it without telling us."

<!-- In your app -->
<button data-testid="add-to-cart-btn">Add to Cart</button>
<span data-testid="cart-count">3</span>

// In tests
await page.getByTestId('add-to-cart-btn').click();
await expect(page.getByTestId('cart-count')).toHaveText('3');

Custom attribute in config:

// playwright.config.ts
use: { testIdAttribute: 'data-test' }  // or 'data-cy', 'data-qa'

When to use test IDs: no accessible role/text, many similar elements, or dynamic SKU grids:

await page.getByTestId('product-card-SKU123').click();
await expect(page.getByTestId('inventory-count')).toContainText('left');
⚠️ Fallback

CSS Selectors (When Necessary)

CSS is like memorizing the paint color of a door — works until someone repaints. Use only when semantic locators fail.

await page.locator('.product-card').first().click();
await page.locator('[data-product-id="12345"]').click();
await page.locator('button[type="submit"]').click();
await page.locator('.product-grid > div:first-child').click();
await page.locator('input:enabled').fill('test');
🔗 Precision

Chaining and Filtering

On a crowded shelf of products, you don't grab the first box — you find the one labeled "Laptop", then press its Add to Cart button.

const productCard = page.locator('.product-card').filter({ hasText: 'Laptop' });
await productCard.getByRole('button', { name: 'Add to Cart' }).click();

const expensiveProducts = page.locator('.product-card').filter({
  has: page.getByText('$500', { exact: false }),
});

await page.getByRole('navigation').getByRole('link', { name: 'Electronics' }).click();
📋 Lists

Working with Lists

Product grids are like a row of identical cereal boxes — you need first(), nth(), or a loop to pick the right one.

const products = page.getByTestId('product-card');
const count = await products.count();

await products.first().click();
await products.last().click();
await products.nth(2).click();  // Third item (0-indexed)

for (const product of await products.all()) {
  const name = await product.getByRole('heading').textContent();
  console.log(name);
}
🛒 Real-Life Example

E-Commerce Locator Patterns

Reusable patterns are like a shopping checklist template — write once, reuse on every product.

2
Product Card Helper
async function getProduct(page, productName: string) {
  const card = page.locator('[data-testid="product-card"]').filter({
    hasText: productName,
  });
  return {
    card,
    name: card.getByRole('heading'),
    price: card.getByTestId('product-price'),
    addToCart: card.getByRole('button', { name: 'Add to Cart' }),
    image: card.getByRole('img'),
  };
}

const laptop = await getProduct(page, 'MacBook Pro');
await expect(laptop.price).toHaveText('$1,299.00');
await laptop.addToCart.click();
3
Cart Row & Checkout Section
function getCartItem(page, productName: string) {
  const row = page.getByRole('row').filter({ hasText: productName });
  return {
    row,
    quantity: row.getByRole('spinbutton'),
    remove: row.getByRole('button', { name: 'Remove' }),
    subtotal: row.getByTestId('item-subtotal'),
  };
}

const shippingSection = page.getByRole('group', { name: 'Shipping Address' });
await shippingSection.getByLabel('Street Address').fill('123 Main St');
await shippingSection.getByLabel('City').fill('San Francisco');

await page.getByRole('checkbox', { name: 'Electronics' }).check();
await page.getByRole('combobox', { name: 'Sort by' }).selectOption('price-low-high');

🔧 Tools

Debugging Locators

When lost in a store, you ask for help. Playwright gives you three helpers:

  • Inspector — npx playwright test --debug — hover elements, try locators, step through tests
  • Codegen — npx playwright codegen https://www.saucedemo.com — click elements, get recommended locators copied
  • Console in UI/debug mode — count matches, list button text, inspect nodes
await page.locator('.product-card').count();
await page.getByRole('button').allTextContents();
await page.locator('.cart-item').evaluateAll(els => els.map(e => e.textContent));
✓

Quick tip: Run codegen on Sauce Demo and compare suggested locators to the brittle .shopping_cart_badge from Topic 2.

⚠️ Watch Out!

Common Mistakes

  • ❌ CSS class locators everywhere: .btn-primary.add-cart breaks on every redesign.
    ✅ Start with getByRole — classes are a last resort.
  • ❌ XPath for simple buttons: Long paths like //div[3]/span/button are fragile and unreadable.
    ✅ Use roles or test IDs — XPath only for truly complex DOM cases.
  • ❌ Overly broad text: getByText('$') matches every price on the page.
    ✅ Be specific — getByText('$129.99') or filter within a product card.
  • ❌ Skipping codegen: Guessing locators wastes hours.
    ✅ Let Playwright suggest — then pick the highest item in the hierarchy.
📝 Summary

Key Takeaways

  • Prefer role-based locators — getByRole() matches user perception and survives refactoring
  • Text locators are stable — users see text; so should your tests
  • Test IDs create contracts — explicit agreement between devs and QA
  • CSS/XPath are fallbacks — use only when semantic locators fail
  • Chain for precision — .filter() and nested locators narrow crowded pages
  • Use codegen — let Playwright suggest the best locator, then upgrade to roles if needed
