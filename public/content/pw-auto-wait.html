Auto-Wait & Assertions

This is Playwright's superpower. Understanding auto-wait is the difference between tests that work sometimes and tests that work always.

🎯 What is it?

Auto-Wait & Web-First Assertions

Imagine ordering coffee: you don't grab the cup the millisecond you press "Order" — you wait until the barista hands you a full cup. Playwright does the same for clicks and fills: it waits until the element is actually ready before acting.

Web-first assertions are the other half — instead of checking the cart total once and hoping the API finished, Playwright retries until the total appears or a timeout hits.

⚠️ The Pain

The Problem: Race Conditions

E-commerce sites are asynchronous. When you click "Add to Cart":

  1. JavaScript sends an API request
  2. Server processes the request
  3. Response comes back
  4. UI updates the cart count

Your test runs much faster than this. Without proper waiting, you read the cart badge before the UI updates — like checking your mailbox before the postman arrives.

❌
Dangerous: Race Condition
await page.click('.add-to-cart');
const count = await page.textContent('.cart-count');
expect(count).toBe('1');  // Might still be '0'!
⚙️ How It Works

How Auto-Wait Works

When you call await page.getByRole('button', { name: 'Add to Cart' }).click(), Playwright doesn't click immediately. It polls until all actionability checks pass — like a bouncer checking ID, ticket, and dress code before letting you in.

  • Attached — element exists in the DOM
  • Visible — not hidden, not zero-size
  • Stable — not animating or moving
  • Enabled — not disabled
  • Receivable — nothing blocking clicks (overlays)

Only after ALL checks pass does Playwright perform the action.

🛒 Real-Life Example

E-Commerce Auto-Wait Examples

Each action below relies on auto-wait — no sleep() between steps.

1
Add to Cart
test('add product to cart', async ({ page }) => {
  await page.goto('/products/wireless-headphones');

  // Waits: present, visible, stable, enabled, not blocked
  await page.getByRole('button', { name: 'Add to Cart' }).click();
});
2
Checkout Form
test('checkout form', async ({ page }) => {
  await page.goto('/checkout');

  await page.getByLabel('Card Number').fill('4111111111111111');
  await page.getByLabel('Expiration').fill('12/25');
  await page.getByLabel('CVV').fill('123');

  // Waits until "Pay Now" is enabled (e.g. after validation)
  await page.getByRole('button', { name: 'Pay Now' }).click();
});
3
Shipping Dropdown
await page.getByRole('combobox', { name: 'Shipping Method' })
  .selectOption('express');

// Price may update async — use web-first assertion next
await expect(page.getByTestId('shipping-cost')).toHaveText('$15.99');
💻 Code Example

Web-First Assertions

A regular assertion is like glancing at the oven once — if the cake isn't done, you fail. A web-first assertion keeps checking until it's ready (or the timer rings).

❌
Bad — checks once
expect(await page.textContent('.cart-total')).toBe('$129.99');
✅
Good — auto-retries
await expect(page.locator('.cart-total')).toHaveText('$129.99');
📋 Reference

Available Web-First Assertions

// Visibility
await expect(locator).toBeVisible();
await expect(locator).toBeHidden();

// Text
await expect(locator).toHaveText('Expected text');
await expect(locator).toContainText('partial');
await expect(locator).toHaveText(/regex pattern/);

// Form state
await expect(locator).toBeEnabled();
await expect(locator).toBeDisabled();
await expect(locator).toBeChecked();
await expect(locator).toHaveValue('input value');

// Element state
await expect(locator).toBeAttached();
await expect(locator).toHaveAttribute('href', '/cart');
await expect(locator).toHaveClass(/active/);
await expect(locator).toHaveCount(5);

// Page-level
await expect(page).toHaveTitle('Shopping Cart');
await expect(page).toHaveURL(/\/checkout/);
🛒 Real-Life Example

E-Commerce Assertion Patterns

A full purchase flow — every expect retries until the async UI catches up.

test('complete purchase flow', async ({ page }) => {
  await page.goto('/products');

  await page.getByRole('button', { name: 'Add to Cart' }).first().click();
  await expect(page.getByTestId('cart-count')).toHaveText('1');

  await page.getByRole('link', { name: 'Cart' }).click();
  await expect(page).toHaveURL(/\/cart/);
  await expect(page.getByRole('heading', { name: 'Your Cart' })).toBeVisible();
  await expect(page.getByTestId('cart-item')).toHaveCount(1);

  await page.getByRole('button', { name: 'Checkout' }).click();
  await page.getByLabel('Email').fill('test@example.com');
  await page.getByRole('button', { name: 'Continue' }).click();

  await expect(page.getByText('Order Confirmed')).toBeVisible();
});
💻 Code Example

Soft Assertions

expect.soft() is like a checklist inspector — note every problem on the product page, then report all failures at the end instead of stopping at the first missing image.

test('product page has required elements', async ({ page }) => {
  await page.goto('/products/laptop');

  await expect.soft(page.getByRole('img', { name: /laptop/i })).toBeVisible();
  await expect.soft(page.getByTestId('product-price')).toBeVisible();
  await expect.soft(page.getByTestId('product-rating')).toBeVisible();
  await expect.soft(page.getByRole('button', { name: 'Add to Cart' })).toBeEnabled();

  // All failures reported at end of test
});
⏱️ Timeouts

Custom Timeouts

Sometimes checkout or payment needs extra patience — tune timeouts like adjusting an oven timer for a bigger cake.

// Per-assertion (slow payment confirmation)
await expect(page.getByText('Payment processed')).toBeVisible({
  timeout: 30000,
});

// Per-action (slow image load)
await page.getByRole('img', { name: 'Product' }).click({ timeout: 10000 });

// Global config
export default defineConfig({
  use: { actionTimeout: 15000 },
  expect: { timeout: 10000 },
});
🚫 Anti-Patterns

What NOT to Do

1
Manual Sleep
// BAD
await page.click('.add-to-cart');
await page.waitForTimeout(2000);
expect(await page.textContent('.cart-count')).toBe('1');

// GOOD
await page.click('.add-to-cart');
await expect(page.locator('.cart-count')).toHaveText('1');

Fixed sleeps waste time when fast, fail when slow, and differ across CI vs laptop.

2
Redundant waitForSelector
// UNNECESSARY
await page.waitForSelector('.add-to-cart');
await page.click('.add-to-cart');

// CORRECT — auto-wait built in
await page.click('.add-to-cart');
3
Manual Polling Loop
// BAD — reinventing expect()
let cartCount = '0';
for (let i = 0; i < 10; i++) {
  cartCount = await page.textContent('.cart-count') ?? '0';
  if (cartCount === '1') break;
  await page.waitForTimeout(500);
}

// GOOD
await expect(page.locator('.cart-count')).toHaveText('1');
🔧 When Needed

When You DO Need Explicit Waits

Auto-wait handles elements — but sometimes you must wait for network, navigation, or load state before asserting.

// Wait for API after "Load More"
await page.getByRole('button', { name: 'Load More' }).click();
await page.waitForResponse(r =>
  r.url().includes('/api/products') && r.status() === 200
);
await expect(page.getByTestId('product-card')).toHaveCount(20);

// Wait for navigation / URL
await page.getByRole('button', { name: 'Submit Order' }).click();
await page.waitForURL('**/order-confirmation');

// Wait for SPA to settle
await page.goto('/products');
await page.waitForLoadState('networkidle');

// Wait for spinner to leave
await page.locator('.loading-spinner').waitFor({ state: 'hidden' });

⚠️ Watch Out!

Common Mistakes

  • ❌ Using Vitest/Jest expect on raw values: expect(await el.textContent()).toBe('1') — no retry.
    ✅ Use Playwright await expect(locator).toHaveText('1') — web-first retry.
  • ❌ Copying Selenium habits: waitForSelector before every click.
    ✅ Trust auto-wait on actions; use explicit waits only for network/navigation.
  • ❌ Same timeout everywhere: 1s for payment confirmation that needs 30s.
    ✅ Override per assertion for slow e-commerce operations.
  • ❌ Soft asserts for critical path: Using expect.soft on "Order Confirmed" hides checkout failures.
    ✅ Reserve soft asserts for non-blocking UI audits (images, ratings).
📝 Summary

Key Takeaways

  • Auto-wait is automatic — every action waits for actionability
  • Web-first assertions retry — use await expect(locator), not expect(await value)
  • Avoid manual waits — waitForTimeout is almost always wrong
  • Timeouts are configurable — per-assertion, per-action, or global
  • Explicit waits sparingly — network, navigation, load state
  • E-commerce is async — cart, pricing, inventory all benefit
