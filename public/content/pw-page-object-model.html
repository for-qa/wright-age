🎯 What is it?

Page Object Model (POM)

Think of a restaurant: the menu tells customers what they can order (tests), the kitchen workflow knows how dishes are prepared (flows), and each station knows where ingredients live (page objects).

POM wraps each page in a class that owns locators and actions. Tests call productPage.addToCart() instead of repeating raw selectors — one place to update when the cart badge class changes.

⚠️ The Pain

The Problem: Test Maintenance

Without POM, every spec copy-pastes the same locators. When .cart-count becomes .CartBadge__count, you hunt through 50 files — like changing your address in 50 apps instead of one profile.

❌
Duplicated locators across specs

test('can add to cart', async ({ page }) => {

💻 Code Example

Base Page

Shared pieces — header, footer, loading spinner, cart count — live in a parent class every page extends. Like a store's common entrance every department shares.

export class BasePage {
  readonly page: Page;
  readonly header: Locator;
  readonly footer: Locator;
  readonly loadingSpinner: Locator;

  constructor(page: Page) {
    this.page = page;
    this.header = page.getByRole('banner');
    this.footer = page.getByRole('contentinfo');
    this.loadingSpinner = page.getByTestId('loading-spinner');
  }

  async waitForPageLoad(): Promise<void> {
    await this.loadingSpinner.waitFor({ state: 'hidden' });
  }

  async getCartCount(): Promise<string> {
    return await this.header.getByTestId('cart-count').textContent() || '0';
  }

  async goToCart(): Promise<void> {
    await this.header.getByRole('link', { name: 'Cart' }).click();
  }
}
🛒 Real-Life Example

Product Page

One class owns product title, price, quantity, variants, and addToCart() with optional size/color/quantity — tests stay readable.

export class ProductPage extends BasePage {
  readonly addToCartButton: Locator;
  readonly quantityInput: Locator;
  readonly sizeSelector: Locator;

  constructor(page: Page) {
    super(page);
    this.addToCartButton = page.getByRole('button', { name: 'Add to Cart' });
    this.quantityInput = page.getByRole('spinbutton', { name: 'Quantity' });
    this.sizeSelector = page.getByRole('combobox', { name: 'Size' });
  }

  async goto(productSlug: string): Promise<void> {
    await this.page.goto(`/products/${productSlug}`);
    await this.waitForPageLoad();
  }

  async addToCart(options?: { quantity?: number; size?: string }) {
    if (options?.size) await this.sizeSelector.selectOption(options.size);
    if (options?.quantity) await this.quantityInput.fill(String(options.quantity));
    await this.addToCartButton.click();
  }

  async expectProductLoaded(name: string) {
    await expect(this.productTitle).toContainText(name);
    await expect(this.productPrice).toBeVisible();
  }
}

Cart Page

Cart logic — items, promo codes, totals — stays in one file. Filter by product name to update quantity or remove lines.

getCartItem(productName: string): Locator {
  return this.cartItems.filter({ hasText: productName });
}

async applyPromoCode(code: string): Promise<void> {
  await this.promoCodeInput.fill(code);
  await this.applyPromoButton.click();
  await this.waitForPageLoad();
}

async expectCartHasItems(count: number): Promise<void> {
  await expect(this.cartItems).toHaveCount(count);
}

async expectTotal(amount: string): Promise<void> {
  await expect(this.cartTotal).toHaveText(amount);
}
💻 Code Example

Checkout Page

Shipping, payment, and order summary grouped with typed helpers — fill address once, select shipping method, place order.

async fillShippingAddress(address: ShippingAddress): Promise<void> {
  await this.firstNameInput.fill(address.firstName);
  await this.lastNameInput.fill(address.lastName);
  await this.emailInput.fill(address.email);
  await this.addressInput.fill(address.address);
  await this.cityInput.fill(address.city);
  await this.stateSelect.selectOption(address.state);
  await this.zipCodeInput.fill(address.zipCode);
}

async selectShippingMethod(method: 'standard' | 'express' | 'overnight') {
  const options = { standard: this.standardShipping, express: this.expressShipping, overnight: this.overnightShipping };
  await options[method].check();
}

async fillPaymentInfo(payment: PaymentInfo): Promise<void> {
  await this.cardNumberInput.fill(payment.cardNumber);
  await this.expirationInput.fill(payment.expiration);
  await this.cvvInput.fill(payment.cvv);
  await this.nameOnCardInput.fill(payment.nameOnCard);
}
🧩 Reuse

Component Objects

Header, ProductCard, and Footer appear on many pages — extract them like reusable LEGO bricks instead of rebuilding each time.

// components/Header.ts — scoped to banner
export class Header {
  readonly cartCount: Locator;
  constructor(page: Page) {
    const container = page.getByRole('banner');
    this.cartCount = container.getByTestId('cart-count');
    this.cartLink = container.getByRole('link', { name: /cart/i });
  }
  async goToCart() { await this.cartLink.click(); }
}

// components/ProductCard.ts — takes a container locator
export class ProductCard {
  constructor(container: Locator) {
    this.name = container.getByRole('heading');
    this.addToCartButton = container.getByRole('button', { name: 'Add to Cart' });
  }
  async addToCart() { await this.addToCartButton.click(); }
}
🔄 Real-Life Example

Flow Layer

Flows stitch pages into business journeys — "complete checkout" or "search and buy" — so tests don't repeat 15 steps.

export class CheckoutFlow {
  constructor(page: Page) {
    this.cartPage = new CartPage(page);
    this.checkoutPage = new CheckoutPage(page);
  }

  async completeCheckout(data: CheckoutData): Promise<void> {
    await this.cartPage.proceedToCheckout();
    await this.checkoutPage.fillShippingAddress(data.shipping);
    await this.checkoutPage.selectShippingMethod(data.shippingMethod);
    await this.checkoutPage.fillPaymentInfo(data.payment);
    await this.checkoutPage.placeOrder();
  }

  async applyPromoAndCheckout(promoCode: string, data: CheckoutData) {
    await this.cartPage.applyPromoCode(promoCode);
    await this.completeCheckout(data);
  }
}
✅ Tests

Using Page Objects in Tests

Specs read like requirements — add product, verify cart, checkout — not like CSS archaeology.

test('complete purchase with single item', async ({ page }) => {
  const productPage = new ProductPage(page);
  const cartPage = new CartPage(page);
  const checkoutPage = new CheckoutPage(page);

  await productPage.goto('wireless-headphones');
  await productPage.addToCart({ quantity: 1, color: 'Black' });

  await cartPage.goto();
  await cartPage.expectCartHasItems(1);

  await cartPage.proceedToCheckout();
  await checkoutPage.fillShippingAddress(testShipping);
  await checkoutPage.selectShippingMethod('standard');
  await checkoutPage.fillPaymentInfo(testPayment);
  await checkoutPage.placeOrder();

  await expect(page.getByText('Order Confirmed')).toBeVisible();
});

test('complete purchase using flow helper', async ({ page }) => {
  const productPage = new ProductPage(page);
  const cartPage = new CartPage(page);
  const checkoutFlow = new CheckoutFlow(page);

  await productPage.goto('wireless-headphones');
  await productPage.addToCart();
  await cartPage.goto();

  await checkoutFlow.completeCheckout({ shipping: testShipping, shippingMethod: 'express', payment: testPayment });
  await expect(page.getByText('Order Confirmed')).toBeVisible();
});
⚠️ Watch Out!

Common Mistakes

  • ❌ God page object: One 800-line class with every locator on the site.
    ✅ One class per page/section plus small components.
  • ❌ Assertions only in tests, actions only in pages — but locators duplicated in both.
    ✅ Locators live in page objects only; tests call cartPage.expectTotal('$99').
  • ❌ Putting test data inside page classes: Hard-coded emails in CheckoutPage.
    ✅ Pass data from tests or fixtures into fillShippingAddress(data).
  • ❌ Skipping flows and duplicating 10-step checkout in every spec.
    ✅ Use flows for repeated multi-page journeys; keep specs focused on the scenario.
📝 Summary

Key Takeaways

  • Single source of truth — locators defined once in page objects
  • Three layers — Pages (where), Flows (how), Tests (what)
  • DRY — no duplicate locators or setup code
  • Easy maintenance — UI change = one file update
  • Readability — tests read like business requirements
  • Components — reusable Header, ProductCard, etc.
